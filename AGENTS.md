# Repository instructions

- Do not modify application source code, build scripts, project files, or runtime behavior without the user's explicit approval to implement the discussed change.
- Requests to discuss, evaluate, plan, compare options, or answer a question are not approval to write code.
- After a design discussion, wait for a clear implementation instruction such as "реализуй", "делай", or an equivalent explicit authorization before editing code.
- Machine configuration JSON files may be edited only when the user explicitly asks to create or change that configuration.
- All user-facing repository documentation must be written in Russian. Technical identifiers, commands, file names, API names, and code examples may remain in English.
- Documentation must support explicit semantic versioning. Every document in `docs/` must state its document version, status, and last-updated date near the top.
- Use SemVer for documentation: increment MAJOR for incompatible architectural or format changes, MINOR for new documented behavior or substantial sections, and PATCH for corrections or clarifications.
- Record every documentation version in `docs/VERSIONS.md`. When changing documentation, update both the affected document version and the version journal in the same change.
