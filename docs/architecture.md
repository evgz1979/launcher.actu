# Архитектура

- **Версия документа:** 3.0.0
- **Статус:** реализовано
- **Обновлено:** 2026-08-09

## Цель

Хранить описание сервисов рядом с Python-проектами, обнаруживать установленные
на каждом Mac проекты и формировать машинную конфигурацию для Launcher.

Описания проектов и машинные конфигурации хранятся в Git. В них запрещено
размещать секреты, токены и учётные данные.

## Компоненты

### Python-проекты

Проекты располагаются в отдельных каталогах внутри `~/Documents`. Признаки
поддерживаемого проекта:

- корневой `README.md`;
- `pyproject.toml`, `requirements.txt` или Python-файлы в корне;
- необязательный корневой `launcher.json` с описанием сервисов.

Наличие `README.md` и `launcher.json` считается явной регистрацией проекта и
достаточно для обнаружения, даже если Python-код расположен не в корне. Благодаря
этому сам Scanner CLI из репозитория Launcher также попадает в машинный JSON.

Проектный `launcher.json` — источник истины для метаданных сервисов. Пути в нём
по возможности задаются относительно корня проекта.

### Scanner CLI

Отдельная интерактивная Python CLI-утилита сканирует `~/Documents`, распознаёт
Python-проекты, читает или создаёт их `launcher.json` и формирует конфигурацию
текущей машины.

CLI не использует внешние Python-библиотеки. Он отвечает за обнаружение,
проверку, вопросы пользователю, разрешение путей и
обновление машинного JSON. CLI не запускает сервисы.

### Машинные конфигурации

Сформированные конфигурации хранятся в этом репозитории:

```text
configs/<machine-id>.json
```

Каждый файл содержит macOS `LocalHostName` и проекты выбранной машины. Имя
машины должно встречаться только в одной конфигурации.

Это генерируемые файлы, но они отслеживаются Git, чтобы сохранять историю и
видеть различия между компьютерами.

### Launcher в строке меню

Launcher определяет текущий `LocalHostName`, находит совпадающий JSON в
репозиторном `configs/` и запускает только перечисленные там сервисы.

Внизу меню показываются применённая конфигурация и имя машины. При отсутствии
совпадения никакие сервисы не запускаются.

Команды `Reload configuration` и `Open configuration folder` не требуются.
Изменения применяются при следующем запуске Launcher.

Отдельного действия `Open` для сервиса нет. Ручной `Start` запускает или
перезапускает сервис и затем открывает его URL в браузере. Автоматический запуск
при старте Launcher браузер не открывает.

## Поток данных

```text
~/Documents/<project>/launcher.json
                  |
                  | Scanner CLI
                  v
launcher.actu/configs/<machine-id>.json
                  |
                  | чтение при запуске
                  v
             Launcher.app
```

## Источники истины

1. Проектный `launcher.json` хранит переносимые метаданные проекта и сервисов.
2. Машинный JSON хранит выбранные на конкретном компьютере проекты и абсолютные
   пути, необходимые `launchd`.
3. Scanner CLI генерирует машинные записи из проектных файлов.
4. Проектные файлы используют относительные пути, машинные — абсолютные.
5. Секреты запрещены в обоих форматах.
6. Все найденные проекты рассматриваются при каждом сканировании. Постоянное
   отключение проекта задаётся только через `enabled: false` в его `launcher.json`.

## Область сканирования

Первая версия сканирует только непосредственные дочерние каталоги
`~/Documents`. Каталоги `.git`, `.venv`, `node_modules`, `build` и `dist`
игнорируются. Рекурсивный поиск и дополнительные корни можно спроектировать
позднее.
