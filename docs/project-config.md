# Проектный `launcher.json`

- **Версия документа:** 1.0.0
- **Статус:** согласованный проект формата
- **Обновлено:** 2026-08-09

## Расположение

Каждый подключённый Python-проект хранит `launcher.json` в корне рядом с
`README.md`. Файл коммитится в Git-репозиторий самого проекта.

```text
actu/
├── launcher.json
├── README.md
├── pyproject.toml
├── .venv/
└── main.py
```

## Предлагаемый формат версии 1

```json
{
  "version": 1,
  "id": "actu",
  "name": "Actu",
  "enabled": true,
  "services": [
    {
      "id": "viewer",
      "name": "Viewer",
      "command": [".venv/bin/python", "main.py"],
      "port": 8050,
      "url": "http://localhost:8050",
      "autoStart": false
    }
  ]
}
```

## Поля проекта

- `version` — обязательная версия формата, первоначально `1`.
- `id` — обязательный стабильный идентификатор.
- `name` — обязательное отображаемое название.
- `enabled` — необязательное поле, по умолчанию `true`. При `false` проект не
  попадает в машинную конфигурацию.
- `services` — обязательный массив, который может быть пустым.

## Поля сервиса

- `id` — обязательный уникальный внутри проекта идентификатор.
- `name` — обязательное название для меню.
- `command` — обязательный непустой массив команды и аргументов.
- `workingDirectory` — необязательный каталог. По умолчанию используется корень
  проекта; относительное значение разрешается от него.
- `port` — необязательный порт, который Launcher освобождает перед запуском.
- `url` — необязательный адрес для действия открытия в меню.
- `autoStart` — необязательное поле, по умолчанию `false`. Безопасное значение
  не позволяет новому сервису запуститься только вследствие сканирования.

## Пути

Проектная конфигурация должна быть переносимой:

```json
"command": [".venv/bin/python", "main.py"]
```

Scanner CLI преобразует её для конкретной машины:

```json
"command": [
  "/Users/evgz/Documents/actu/.venv/bin/python",
  "main.py"
],
"workingDirectory": "/Users/evgz/Documents/actu"
```

Абсолютные пути допустимы только при реальной привязке к машине; Scanner CLI
должен отдельно предупреждать о них.

## Проверка

Перед использованием Scanner CLI проверяет:

- корректность JSON и поддержку `version`;
- наличие обязательных идентификаторов и названий;
- уникальность идентификаторов сервисов;
- наличие непустой команды;
- допустимый диапазон `port`;
- корректный HTTP- или HTTPS-адрес в `url`;
- существование рабочего каталога и исполняемого файла.

Ошибка должна указывать проект, файл и проблемное поле. Некорректный проект не
добавляется в машинную конфигурацию автоматически.
