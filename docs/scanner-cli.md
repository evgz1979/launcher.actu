# Спецификация Scanner CLI

- **Версия документа:** 3.1.1
- **Статус:** первая версия реализована
- **Обновлено:** 2026-08-09

## Назначение

Scanner CLI обнаруживает Python-проекты в `~/Documents`, помогает создать
отсутствующие проектные `launcher.json` и формирует конфигурацию текущей машины в
репозитории Launcher.

Это отдельная командная утилита. Она не запускает сервисы.

## Первоначальные команды

```bash
./scripts/launcher-config scan
./scripts/launcher-config check
./scripts/launcher-config show
```

- `scan` — интерактивное сканирование и предложение изменений.
- `check` — проверка без записи: отсутствующие и ошибочные файлы, проблемы путей
  и расхождения с машинной конфигурацией.
- `show` — текущая машина и её эффективная конфигурация.

Для изолированной проверки или автоматических тестов доступны параметры
`--documents <path>` и `--repo <path>`.

## Определение машины

CLI использует тот же macOS `LocalHostName`, что и Launcher. Если подходящего
машинного файла нет, `scan` предлагает создать его со стабильным ID,
отображаемым названием и обнаруженным `LocalHostName`.

## Распознавание проекта

Непосредственный дочерний каталог `~/Documents` считается кандидатом, если в нём
есть корневой `README.md` и хотя бы один признак Python-проекта:

- `pyproject.toml`;
- `requirements.txt`;
- Python-файлы в корне.

Проект с корневыми `README.md` и `launcher.json` считается явно настроенным и
обнаруживается без дополнительных признаков Python в корне.

CLI самостоятельно выбирает `.venv/bin/python`, если он существует, иначе
`python3`. Точки входа определяются по корневым Python-файлам с приоритетом
`main.py`, затем `app.py`.

Порт и URL определяются без выполнения проекта: Scanner CLI читает локальные URL
из README и разбирает Python через `ast`, включая константы `HOST` и `PORT`,
`ThreadingHTTPServer`, `HTTPServer`, `TCPServer` и типовые вызовы `run`/`serve`.
Если код однозначно расходится с ранее записанным портом, проектный
`launcher.json` предлагается исправить.

## Алгоритм сканирования

1. Если `launcher.json` существует, проверить его и сравнить с машинной записью.
2. Для корректного файла разрешить относительные пути и предложить обновление.
3. Некорректный файл не перезаписывать, а показать понятные ошибки.
4. При отсутствии файла спросить, нужно ли его создать.
5. После обхода показать общую сводку или diff.
6. Запросить подтверждение перед любой записью.
7. После записи повторно проверить результат.
8. Если конфигурация фактически изменилась и Launcher запущен, автоматически
   перезапустить его через установленный LaunchAgent.

Если изменений нет или Launcher не запущен, перезапуск не выполняется. При
перезапуске сервисы корректно останавливаются и затем вновь запускаются согласно
их `autoStart`.

## Проект без `launcher.json`

Первый вопрос:

```text
Найден Python-проект: /Users/evgz/Documents/actu
Создать launcher.json для этого проекта? [y/N]
```

При согласии CLI сам формирует ID проекта из имени каталога, использует имя
каталога как название и создаёт ID и название сервиса из найденной точки входа.
Эти значения не запрашиваются у пользователя.

Пользователь задаёт порт и URL только тогда, когда они не определены
автоматически, а также необходимость автоматического запуска и подключение
дополнительных найденных Python-файлов.
`autoStart` по умолчанию равен `false`. Перед созданием показывается полный новый
`launcher.json`.

## Отказ от добавления

CLI предлагает:

```text
1. Пропустить сейчас
2. Пометить проект как отключённый для Launcher
```

- «Пропустить сейчас» ничего не записывает и повторяет вопрос при следующем
  сканировании.
- «Пометить как отключённый» предлагает создать минимальный `launcher.json` с
  `enabled: false` и требует отдельного подтверждения.

Scanner всегда рассматривает все проекты текущей машины. Отдельного постоянного
списка игнорирования для машины нет.

## Существующие и удалённые проекты

- Существующие записи обновляются из проектного `launcher.json` после
  подтверждения.
- Отсутствующий на диске проект отмечается как устаревший.
- Устаревшие записи никогда не удаляются автоматически.
- Удаление требует явного подтверждения.

## Формирование машинной конфигурации

Scanner CLI записывает файл в `configs/` этого репозитория, сохраняя машинные
метаданные и формируя `projects` из принятых проектных файлов. Относительные
команды и каталоги преобразуются в абсолютные пути.

Launcher игнорирует неизвестные ему поля машинного JSON.

## Безопасность и Git

- До итогового просмотра и подтверждения запись запрещена.
- Некорректные существующие файлы автоматически не исправляются.
- Пользовательские файлы молча не заменяются.
- Проекты и сервисы без подтверждения не удаляются.
- Найденные Python-файлы во время сканирования не выполняются.
- Секреты и значения переменных окружения в JSON не сохраняются.
- Коммит и отправка в Git выполняются отдельно; CLI не публикует изменения.

## За пределами текущей реализации

- графический редактор;
- выполнение или автоматическое исследование Python entry point;
- произвольно глубокий рекурсивный поиск;
- горячая перезагрузка конфигурации в Launcher;
- открытие каталога конфигурации из меню;
- автоматические `git commit`, `pull` и `push`.
