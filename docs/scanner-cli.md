# Спецификация Scanner CLI

- **Версия документа:** 4.0.0
- **Статус:** реализовано
- **Обновлено:** 2026-08-29

## Назначение

Scanner CLI помогает создавать, проверять и просматривать проектные
`launcher.json` в `~/Documents`. Он не формирует машинные конфигурации и не
является обязательным посредником между проектом и Launcher.

## Команды

```bash
./scripts/launcher-config scan
./scripts/launcher-config check
./scripts/launcher-config show
```

- `scan` — интерактивно предлагает создание и уточнение проектных файлов;
- `check` — без записи проверяет все непосредственные папки с `launcher.json`;
- `show` — выводит эффективный список включённых проектов и абсолютные пути.

Для изолированной проверки доступны параметры `--documents <path>` и
`--repo <path>`. `--repo` нужен только для перезапуска собранного приложения.

## Два вида обнаружения

Runtime Launcher признаёт проектом только непосредственную папку с
`launcher.json`.

Интерактивный `scan` дополнительно ищет кандидатов для первоначальной настройки.
Кандидатом считается папка с корневым `README.md` и одним из признаков:

- `pyproject.toml`;
- `requirements.txt`;
- Python-файл в корне.

Папка с `launcher.json` всегда рассматривается независимо от `README.md` и
языка проекта.

## Создание и уточнение

Для Python-кандидата без конфигурации CLI спрашивает, создавать ли
`launcher.json`. При согласии он:

- формирует ID и названия из имени каталога и точек входа;
- выбирает `.venv/bin/python`, если файл существует, иначе `python3`;
- предлагает `main.py`, затем `app.py`, затем остальные корневые Python-файлы;
- пытается определить порт и URL по README и Python AST;
- использует безопасный `autoStart: false` по умолчанию;
- показывает diff и просит итоговое подтверждение перед записью.

Для существующего файла CLI может предложить однозначное уточнение `port` и
`url`. Некорректный файл автоматически не перезаписывается.

## Отказ от добавления

CLI позволяет разово пропустить кандидата или создать для него минимальный
файл с `enabled: false`. Разовый пропуск ничего не записывает. Отключённый файл
явно фиксирует, что проект не должен появляться в Launcher.

## Применение изменений

Если проектные файлы не изменились, Launcher не перезапускается. После
подтверждённой записи CLI перезапускает уже работающий Launcher, чтобы приложение
заново просканировало каталог и применило `autoStart`.

## Безопасность и Git

- исходники найденных проектов не выполняются во время сканирования;
- до итогового подтверждения запись запрещена;
- файлы и сервисы молча не удаляются;
- секреты и переменные окружения в JSON не сохраняются;
- commit и push CLI не выполняет.

## Ограничения

- только непосредственные дочерние каталоги одного корня;
- эвристическое создание ориентировано на Python;
- графического редактора и горячей перезагрузки нет;
- дополнительные корни и рекурсивный поиск не реализованы.
